# 安装位置登记与数据统一（PHL / PHL Lite）

> 适用版本：PHL Lite 1.2.9+、PHL 2.0.13+
> 本文是给两边开发（含 PHL 开发 AI）的规范与实施说明；Lite 侧代码已按此实现，
> PHL 侧待做项见文末「分工」。

## 1. 要解决的问题

1. 用户把 PHL 装到非默认目录后，再装 PHL Lite 时安装器仍会装到默认目录，
   两个程序不在同一个文件夹，`data/` 也就没有共用。
2. PHL 可能在 `data-root.txt` 里记录过另一个数据根；只联安装位置不够，
   数据根不一致时「同目录」也不等于「共用数据」。
3. 数据格式上，共享的 `settings.yaml` / `Timetable` / `School` / `agent/` 已经是
   同一份；`Schedule` 也是同一份共享格式，但 PHL 自己的日历（重复日程、提醒、
   附件、颜色等）是私有模型，只把「可表示的字段」镜像进共享文件——
   用户希望 **Lite 读 PHL 的日程时忽略多余字段，Lite 新建日程时按 PHL 的共享
   格式写、缺省项用默认**，这样 PHL 读 Lite 的日程不需要额外翻译。

**非目标**：不合并两边的私有缓存（`phl/` 与 `phll/`），不自动迁移/删除用户数据，
不要求 PHL 的私有日历模型与 Lite 完全相同（那需要 PHL 大改提醒/重复/UI，另立任务）。

## 2. 安装登记：固定文件、两边共写

### 2.1 位置

| 平台 | 路径 |
|---|---|
| Windows | `%LOCALAPPDATA%\PingheSeries\installations.ini` |
| macOS | `~/Library/Application Support/PingheSeries/installations.ini` |

每用户一份、无需管理员；两个程序的安装器与应用启动流程都读写它。
测试/自动化可用环境变量 `PHLL_INSTALL_REGISTRY`（Lite）覆盖，**不要**在测试里
碰真实文件。

### 2.2 格式（INI）

```ini
[phl]
installed=1
path=C:\Users\me\Programs\PH Launcher
data_root=C:\Users\me\Programs\PH Launcher\data
version=2.0.13
updated_at=2026-11-10T18:20:00+08:00

[phl-lite]
installed=1
path=C:\Users\me\Programs\PH Launcher
data_root=C:\Users\me\Programs\PH Launcher\data
version=1.2.9
updated_at=2026-11-10T18:25:00+08:00
```

- 节存在且 `installed` 不是 `0/false/no` → 视为已安装；卸载时删除整节。
- `path`：安装目录（Windows = exe 所在目录；macOS = `.app` 所在目录）。
- `data_root`：该程序**实际使用**的数据根（可能不等于 `path\data`，见 §3.2）。
- `version` / `updated_at`：便于排查，不参与判定。
- 读取必须容错（文件缺失/损坏 → 视为未安装）；写入必须读-改-写、原子替换，
  **绝不能覆盖对方的节**。

### 2.3 读写时序

| 时机 | 写入方 | 动作 |
|---|---|---|
| 安装器启动（目录页之前） | 安装器 | 读对方 `path`/`data_root`，决定默认安装目录/数据根 |
| 安装完成 | 安装器 | 写自己的 `[phl]` / `[phl-lite]` 节 |
| 卸载（路径匹配时） | 卸载器 | 删除自己的节，保留对方节 |
| 应用启动 | 应用 | 更新自己的 `path`/`data_root`/`version`（用户手移目录后自愈） |

## 3. 安装器默认路径联动

### 3.1 读取顺序（两边一致）

1. 登记文件里对方的 `path`，且该目录下确实有对方主程序
   （PHL：`PH Launcher.exe`；Lite：`PingheLauncherLite.exe`）→ 用它作默认安装目录。
2. 旧版程序没写登记时：查 `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall`
   下的卸载项，`DisplayName` 匹配对方程序名且 `InstallLocation` 有值且主程序存在
   → 用它。
3. 标准默认目录有对方主程序：
   `%LOCALAPPDATA%\Programs\PH Launcher`（两边的 per-user NSIS 默认）。
4. 都没有 → 自己安装器的标准默认目录。

用户始终可以在目录页改；改了之后安装器按新目录写登记（数据根按 §3.2）。

### 3.2 数据根

- 登记里对方有 `data_root` → 默认采用它；否则用 `$INSTDIR\data`。
- 安装器把采用的数据根写进自己的 `data_root`，应用启动时按它解析数据目录。
- **不自动迁移数据**：数据根为空/不存在时创建目录，但绝不复制、覆盖、删除。
- 旧 MSI Lite 用户的数据在 `%LOCALAPPDATA%\Programs\PingheLauncherLite\data`，
  仍按原有规则（目标为空且用户确认才复制）；旧目录保留。

### 3.3 关键实现（Lite 已做）

- `installer/PingheLauncherLite.nsi`：`.onInit` 读取登记/注册表/默认路径，
  `StrCpy $INSTDIR` 设置目录页默认值；安装完成写 `[phl-lite]`；
  卸载 `DeleteINISec` 只删自己的节。
- `hellopinghe/install_registry.py`：INI 读写（原子、容错、保留对方节）。
- `hellopinghe/paths.py`：安装版启动时优先采用登记里的 `data_root`。
- `hellopinghe/app/__main__.py`：启动时 `record_self()` 更新自己的条目。

PHL 侧实现见提示词文件：`docs/PHL开发AI提示词-安装登记与数据统一.md`。

## 4. 数据格式标准（“不需要翻译”的确切含义）

共享文件（两个程序直接读写同一份，**格式相同**）：

| 文件 | 标准 | 说明 |
|---|---|---|
| `settings.yaml` | 块级读改写，保留未知字段/注释 | `accounts` / `lessons` / `ai` / `ui` / `phix` / `secrets_extra` 已同格式 |
| `Schedule` | `{version, kind:"pinghe-schedule", app, updated_at, events[], lastId}` | 事件 `{id, day, time, title, note, created}`；两边都保留未知字段 |
| `Timetable` | 按天课卡 JSON | PHL 目前整文件重建会丢 Lite 字段，需改成“读-改-写 + 保留未知字段” |
| `School` | 学校快照 JSON | 同上 |
| `agent/` | 会话 JSON | PHL 目前整文件重建；需保留 Lite 写入的额外字段 |

私有目录（各自保留，不要求相同）：

- `phl/`：PHL 私有（launcher/credentials/ai-history/profile…）。
- `phll/`：Lite 私有（缓存、会话、偏好、心履镜像…）。

### 4.1 Schedule 的“多余信息”规则

PHL 私有日历字段（`repeatWeekdays`、`end`、提醒、颜色、附件、`reminderState`）
**不写进共享 `Schedule`**；共享文件只保留可表示的
`day/time/title/note`（+ `id/lastId/created`）。

- **Lite 读 PHL 的日程**：只取上述字段，多余字段忽略（但写回时保留，不能抹掉）。
- **Lite 新建日程**：按共享格式写（不写 PHL 私有字段）；PHL 读取后按自己的默认
  补 `end`（60 分钟，最晚 23:59）、无重复、无提醒——这就是“缺省项用默认”，
  不需要额外的格式翻译层。
- **PHL 读 Lite 的日程**：`shared-schedule.cjs` 的 `toLauncherEvents()` 已经这样
  做（`end = start + 60`）；保持即可，不要把 PHL 私有字段塞回共享文件。

### 4.2 验证（Lite 已做）

`scripts/test_schedule_compat.py` 用 PHL 的 `electron/shared-schedule.cjs` 做真实
读写验证：

- Lite `events_add()` 写入 → PHL `readSchedule()` 读出相同事件，
  `toLauncherEvents()` 得到 `end = start + 60 分钟`。
- PHL `upsertEvents()` 写入 → Lite `events_list()` 读出相同事件。
- 两边交替新增时 `lastId` 高水位生效，id 不复用。
- 顶层/事件上的未知字段在 Lite 写回后仍保留。

## 5. 兼容与迁移

| 场景 | 行为 |
|---|---|
| 旧版 PHL 未写登记 | 安装器按注册表 `InstallLocation` → 标准默认目录兜底；应用启动后补写登记 |
| 旧版 Lite（MSI，未写登记） | 同上；旧 MSI 数据不自动合并，原目录保留 |
| 用户改过 PHL `data-root.txt` | 登记 `data_root` 记录实际数据根；Lite 安装时采用，应用启动读登记 |
| 用户手移安装目录 | 应用启动 `record_self()` 更新 `path`；对方下次安装/启动看到新路径 |
| 登记文件损坏 | 读取视为未安装；下次安装/启动重写（不删数据） |
| 两边同时写登记 | INI 原子替换；后写者胜（字段少、冲突面小）；数据文件另有互斥锁 |

## 6. 安全边界

- 安装/卸载绝不 `RMDir /r` 安装目录；只删自己的程序文件/快捷方式/注册键/登记节。
- 不自动复制、覆盖、删除对方数据；旧数据迁移只复制、不删除。
- 共享文件写入必须读-改-写、原子替换、保留未知字段。
- 登记文件与数据根路径只接受绝对路径；不跟随/写入用户未选择的位置。
