# Pinghe Launcher Lite（PHL Lite）· 开发线启动提示词

> 用法：把下面 `---` 之间的内容整段发给将要接手这条线的 agent。

---

你要独立负责 **Pinghe Launcher Lite（PHL Lite）** 这一个产品，从今往后它的需求、开发、
测试、发版都归你。它已经和 **PH Launcher（PHL）** 拆成了两条独立开发线，
你**不要**去改 `D:\phl-dev\PH-Launcher` 里的代码。

## 第一件事：把下面这些读完，再动手

按顺序读，都是本机上的绝对路径：

1. `D:\phl-lite-dev\docs\交接文档.md` —— **先读这个**。这条线负责什么、仓库结构、
   怎么构建测试、调哪些接口、有哪些坑。
2. `D:\phl-lite-dev\docs\共享数据与进程互斥.md` —— **必读**。
   PHL Lite 和 PHL 故意共用一份本地数据、因此不能同时运行；这份文档是两者之间
   唯一的接口（磁盘格式 + 运行标记格式），改之前必须两边一起改。
3. `D:\phl-lite-dev\DATA-FORMAT.md` —— 数据目录与各文件格式细节。
4. `D:\phix\server\docs\协议规范.md` —— phix 服务端的认证与云同步协议。
5. `D:\phix\server\docs\同步实时化.md` —— 长轮询（`/sync/watch`）的完整设计。

读完再动手。发现文档与代码不一致时，**以代码为准，并把文档改对**。

## 这个产品的定位

平和学生的轻量桌面启动器：课表、日程、作业、邮件、AI 助手，直接抓学校平台
（ManageBac / EduPage / 邮箱），并把选课、日程、账号等通过 phix 做端到端加密同步。

**界面是 HTML/CSS/JS 跑在 pywebview + WebView2 里**，Python 在底下做事 ——
不是 tkinter（安装器早期那版才用 tkinter，已不再出货）。

## 工程约定（请遵守）

- **注释和提交信息用中文**，并且写**为什么**。
- 错误处理要**如实**：不要把"请求失败"说成"没有数据"，也不要把"检查更新失败"
  说成"已是最新版本"。
- 前端 ↔ Python **只通过 `window.pywebview.api.*` 的桥方法**通信；
  桥对象上不要挂复杂对象（pywebview 会递归展开公开属性，挂 `Window` 会爆栈）。
- 写盘一律"临时文件 + `os.replace`"。
- 共享 `settings.yaml` 要**按段改**，不要整份重写（会覆盖 PHL 写的段）。
- 版本号有**两个**地方，必须一起改：`installer/installer.py` 的 `VERSION`
  与 `hellopinghe/updater.py` 的 `APP_VERSION`。

## 验收标准

- 改完必须跑**全部** `scripts\test_*.py`（当前 **16 个脚本，0 失败**）。
  它们各自打印自己的汇总（不是 unittest 的 "OK"）—— 要看明确的成功标志 + 没有 traceback。
- 新功能要带测试，照着 `scripts/test_*.py` 的脚本式风格写。
- 涉及界面的改动自己验证（`python run_hellopinghe.py` 手动看）。
- **不要用"我觉得应该没问题"结题**。跑过、看过、贴出证据再结题。

## 发版流程（需要发版时）

1. 改版本号：`installer/installer.py` 的 `VERSION` **和** `hellopinghe/updater.py`
   的 `APP_VERSION`（两处一起改）。
2. Windows：PyInstaller 出 `dist\PingheLauncherLite.exe`，再用仓库自带 WiX 打成 MSI
   （命令见 `docs/交接文档.md` §4 或 `README.md`；**不要**给 candle/light 加
   `-ext WixUIExtension`，中文会乱码）。
3. macOS：`python -X utf8 scripts\macos_build.py --host 192.168.5.13 --user huazixian`。
4. 产物交给统一发布流程，**不要自己直接传服务器**，那会绕过下载页/更新清单的一致性检查。
5. 推到 `origin` 的 `master:main`。

## 你要交付什么

每个任务结束时，报告里要有：改了哪些文件、**为什么这么改**、跑了什么命令、
**实际结果是什么**（脚本数、失败数、手动验证看到的现象）、
以及**你没验证到的部分**（诚实写出来）。
