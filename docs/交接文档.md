# Pinghe Launcher Lite（PHL Lite）· 交接文档

> Python + pywebview 桌面启动器，面向平和学生的轻量版：课表、日程、作业、邮件、AI 助手。
> 仓库：`D:\phl-lite-dev`　当前版本：**1.2.8**　本文最后核对：2026-11-10

---

## 1. 这条线负责什么、不负责什么

**负责**：PHL Lite 自己这个程序的全部 —— 界面、本地数据、与 phix 的同步、
应用内自动更新、打包（Windows 的 MSI / 便携 exe，macOS 的 dmg/zip）与发布。

**不负责**：

- **PH Launcher（PHL）**：那是 `D:\phl-dev\PH-Launcher`，Electron 的另一套实现，
  现在是独立开发线。两边**共用一份本地数据**（见 §6），但代码互不依赖。
- phix 服务端 / 官网、心履 —— 都是别的仓库。

**与 PHL 的唯一耦合点**是磁盘格式和运行标记格式，必须两边一起改，
见 §6 与 `docs/共享数据与进程互斥.md`。

## 3. 仓库结构与关键文件

| 路径 | 作用 |

| `hellopinghe/cloudsync.py` | 同步引擎 + `PhixClient`（HTTP、信封、超时） |

| `hellopinghe/updater.py` | 自动更新：`APP_VERSION`、检查、替换、`about` 需要的手动检查 |
| `hellopinghe/shareddata.py` | **与 PHL 的进程互斥**（运行标记 + 心跳）+ 共享文件读写 |
| `hellopinghe/paths.py` | 数据目录解析（`PHLL_DATA_DIR` / `portable.flag` / `~/.hellopinghe`） |
| `hellopinghe/tray.py` | 托盘 |
| `hellopinghe/managebac/`、`edupage` 相关 | 平台抓取与解析 |
| `ui/index.html`、`ui/app.js`、`ui/styles.css` | 前端界面（HTML/CSS/JS，跑在 WebView2 里） |
| `ui/account-ui.js` + `ui/account-bridge.js` | 账号与首次启动界面。`account-ui.js` 与 PHL 的 `src/account-ui.js` **逐字节相同**（SHA256 一致，改一处必须同步另一处）；`account-bridge.js` 是**宿主适配层**，两边本来就不同（PLL 映射到 `window.pywebview.api.*`，PHL 映射到 `window.ph.*`），别拿它当"应当逐字节相同"的依据 |
| `installer/PingheLauncherLite.nsi` | **Windows 正式安装入口**（标准 NSIS MUI2）；`scripts/build_windows.py` 校验双版本号后编译 |

| `scripts/` | 构建脚本（Windows NSIS / macOS）与**全部测试脚本** `test_*.py` |
| `tools/wix314/` | 历史 MSI 构建工具（1.2.8 起不再用于发布，仅保留供回看旧产物） |

## 4. 构建 / 运行 / 测试

```powershell
cd D:\phl-lite-dev

python run_hellopinghe.py          # 开发运行

# 测试：18 个脚本，逐个跑。两种风格都有：5 个是 unittest（test_about / test_installer_nsis /
# test_mail_auth_error / test_sync_watch / test_updater，输出 Ran N tests ... OK），
# 其余 13 个是脚本式（各自打印汇总）
Get-ChildItem scripts\test_*.py | ForEach-Object { python -X utf8 $_.FullName }

# Windows 打包（NSIS）
python -m PyInstaller --noconfirm --clean PingheLauncherLite.spec   # → dist\PingheLauncherLite.exe
python -X utf8 scripts\build_windows.py                            # → dist\PingheLauncherLite-<版本>-Setup.exe
```

> 安装包默认装到 `%LOCALAPPDATA%\Programs\PH Launcher`（与 PH Launcher 2.0.13 一致），
> 并在该目录创建 `data/` + `portable.flag`，两个程序共用数据。安装/卸载只动 Lite
> 自己的 exe、卸载器、快捷方式和注册键；**绝不递归删除** `data/` 或 PHL 文件
> （测试在 `scripts/test_installer_nsis.py`，含 PHL 卸载脚本的反向守护）。
>
> 旧 MSI 构建方式（`installer/PingheLauncherLite.wxs` + WiX）已不再发布。
> 给 `candle`/`light` **不要加** `-ext WixUIExtension`（历史坑，中文会乱）。

macOS 产物在局域网 Mac 上构建：

```powershell
python -X utf8 scripts\macos_build.py --host 192.168.5.13 --user huazixian
```

## 5. 调用的服务端接口

全部打到 phix（`https://phix.ing`）：

| 用途 | 端点 |
|---|---|
| 登录/注册/刷新/改密/恢复 | `/api/v1/auth/*` |
| 清单 / 读写对象 / 批量 | `/api/v1/sync/manifest`、`/sync/objects/<name>`、`/sync/objects/batch` |
| **长轮询** | `GET /api/v1/sync/watch?cursor=` |
| 应用内更新 | `GET /api/v1/update/check?product=phl-lite&platform=win|mac` |

另外还会直接抓学校平台（ManageBac / EduPage / 邮箱）—— 那是另一条链路，
见 `hellopinghe/managebac/` 与相关模块。

**权威文档**：`D:\phix\server\docs\协议规范.md`（协议）、
`D:\phix\server\docs\同步实时化.md`（长轮询）。

**长轮询最容易写错的一条**：`changed=false` 有两种含义相反的情况 ——
**没有** `retry_after` 是正常超时（立刻再挂），**有** `retry_after` 是服务端名额满了
（必须先等）。搞混一边是热循环、另一边是延迟消失。

## 6. 本地数据

- 数据目录解析：`PHLL_DATA_DIR` → 安装目录里有 `portable.flag` 就用 `<安装目录>/data`
  → 否则 `~/.hellopinghe`。1.2.8 起默认安装目录是
  `%LOCALAPPDATA%\Programs\PH Launcher`（与 PHL 相同），所以新装用户天然共用同一份 `data/`。
- **旧 MSI 用户**：数据在旧的 `%LOCALAPPDATA%\Programs\PingheLauncherLite\data`；
  新安装器**不会自动合并**，旧目录原样保留。若目标 `data/` 已有 PHL 数据，Lite 也不会
  把 `~/.hellopinghe` 的旧数据自动并进去（`paths.phl_shared_data_present` 守门，
  见 `scripts/test_shareddata_mutex.py`）。迁移需用户确认后手工处理。
- 与 PHL **共用** `settings.yaml`、`Schedule`、`Timetable`、`School`、`agent/`；
  自己的私有数据在 `phll/`（对方的在 `phl/`）。
- **两个程序不能同时运行**：用 `.pll-running` / `.phl-running` 标记 + 30 秒心跳 +
  90 秒过期判定来拦。完整协议、判决顺序、手工排查、以及一个刚修掉的跨语言格式坑，
  见 **`docs/共享数据与进程互斥.md`** —— 改互斥逻辑之前必须读它。
- 细节格式见 `DATA-FORMAT.md`。

## 7. 开发思路与约定

- **注释和提交信息用中文**，写**为什么**。代码库里到处是"以前怎么踩坑的"说明。
- 错误处理**如实**：不要把"请求失败"说成"没有数据"或"已是最新版本"。
- 前端与 Python 之间**只通过 `window.pywebview.api.*` 的桥方法**通信；
  pywebview 会把 js_api 对象的**公开属性递归展开**成 JS 接口，所以桥对象上
  **不要挂复杂对象**（公有的 `Window` 会让它去遍历 `window.native` 直接爆栈 —— 注释里记着）。
- 写盘一律"临时文件 + `os.replace`"。
- 测试脚本两种风格都有：多数是**脚本式**（`def main()` + `check(cond, msg)`），
  `test_about` / `test_installer_nsis` / `test_mail_auth_error` / `test_sync_watch` /
  `test_updater` 是 unittest —— 新测试照着 `scripts/test_*.py` 的现有风格写即可。
- 版本号在两个地方，必须一起改（见 §2）。

## 8. 已知的坑与禁忌

1. **`VERSION` 与 `APP_VERSION` 必须一起改**，否则更新检查会拿旧版本号比对
   （`scripts/build_windows.py` 已加一致性校验，不一致直接拒绝出包）。
2. **共享文件不要整份重写**（会覆盖 PHL 刚写的段）。
3. **运行标记格式是跨语言接口**：本程序写 snake_case、PHL 写 camelCase，
   两边**都要写两种、读两种**。只认一种会让跨程序的心跳失效
   （2026-10-12 实测确认并修复，测试在 `scripts/test_shareddata_mutex.py`）。
4. **「关于软件」的"检查失败"绝不能显示成"已是最新版本"** —— 两者是相反的状态。
5. **Windows 安装包/自更新都是 NSIS Setup**（`win-nsis` 平台），不要再裸复制覆盖 exe：
   那会绕过 NSIS/MSI 的版本登记与卸载，安装失败还可能把旧程序弄没。
   旧版 `platform=win` 的裸 exe 渠道仅用于把 1.2.7 安全升到 1.2.8，不能删。
6. **默认装到 PHL 同目录**后，卸载/安装都只能碰 Lite 自己的文件；
   绝不 `RMDir /r` 安装目录（会删掉共用 data 与 PHL 文件）。测试在
   `scripts/test_installer_nsis.py`。
7. **静默预下载不等于静默安装**：下载可以后台进行，安装必须用户点按钮；
   取消只关卡，跳过才停止下载并清缓存。检查失败/下载失败/已是最新是三种状态。
8. macOS 未签名：用户需右键 →「打开」一次。
9. 写 PowerShell 脚本要**带 UTF-8 BOM**（PS 5.1 否则按 ANSI 读，中文全乱）。
